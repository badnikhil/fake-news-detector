## 3.6 Adversarial / edge-case behaviour

| Case | Expected behaviour | Where it is handled |
|---|---|---|
| Satire URL (theonion.com, fakingnews.com) | **R0 → FAKE** with reason "originates from a satire/hoax site"; satire hits as *evidence* get w_s = 0 and a warning, never a verdict | `sources.yaml` tier 0, `fusion/rules.py` |
| Opinion piece ("I think the budget should…") | Opinion/modal cues penalise claim scores (−0.8 / −0.5); few or no check-worthy claims → mostly NEUTRAL evidence → **R1/R9 UNVERIFIABLE** with uncertainty text | `claims/heuristics.py` |
| Non-English text | Out of scope (English only). Returns UNVERIFIABLE with the uncertainty text "English input only" (a `422` is also acceptable if implemented as input validation) `[assumption — master doc does not specify]` | `api/schemas.py` |
| Empty / < 20-token input | `422` validation error, UI shows inline message | `api/schemas.py` |
| Paywalled / JS-heavy URL | `trafilatura` → `newspaper3k` fallback → `502 {"error":"extraction_failed"}`; UI suggests pasting the text | `ingest/url_extract.py` (risk R5) |
| No internet in `MODE=online` | Each source times out at 6 s, pipeline degrades to the offline index (NFR-8); never 500. Switch to `MODE=offline` for a fast demo | `evidence/online.py`, `offline_index.py` |
| Single reliable source only | **R8** tie-break with `p_fake`; otherwise UNVERIFIABLE "only one source" | `fusion/rules.py` |
| Very long article (> 60 sentences) | Top-k = 5 claims only; head-truncation to 256 tokens for the classifier | `claims/rank.py`, `models/predict.py` |

## 3.8 Likely viva questions

| Question | Model answer |
|---|---|
| What does macro-F1 ≥ 0.55 on 5 classes actually mean? | Chance is 0.20; PARTIALLY TRUE and MISLEADING are hard even for humans. 0.55 macro-F1 with high FAKE/REAL F1 and honest UNVERIFIABLE precision is a realistic student-scale result; we report per-class numbers, not just the average. |
| Why is UNVERIFIABLE precision a target and not recall? | Because saying "cannot tell" is a safe answer, we must prove we do not abuse it: when we say UNVERIFIABLE, it should genuinely lack evidence ≥ 70 % of the time. |
| What does the ablation prove? | That evidence and stance, not writing style, carry the verdict: classifier-only is at best a style estimate; adding evidence gives the largest jump; temporal adds the MISLEADING class. |
| How do you know the Live Claims labels are right? | Gold labels come from published fact-checks (PolitiFact, Snopes, AltNews, BOOM), mapped to our 5 classes; each item double-labelled with κ reported. |
| Why not report the ~99 % ISOT number as your headline result? | It is leakage: "(Reuters)" datelines and source tokens predict the label. Our cross-dataset table shows the drop after artefact removal. |
| What is the single most common failure? | Retrieval failure on very recent or hyper-local claims → UNVERIFIABLE, and NLI mislabelling long evidence (risk R6); we cap passages at 3 sentences and let fact-checker ratings override NLI. |
| How does the system behave with no evidence but a very "fake-looking" style? | R1 fires first → UNVERIFIABLE. The style score is shown as a caption only; it cannot produce FAKE without evidence. |
| Is the latency acceptable? | Median ≤ 15 s online (search-bound), ≤ 5 s offline, ≤ 1 s classifier-only — measured over 50 requests each, p90 reported. |

# 4. Working Project — Innovation & UX (5 marks)

## 4.1 What we built / delivered

**Differentiators** (none of the compared systems has all five): (1) five verdicts including a first-class UNVERIFIABLE; (2) every evidence card carries source tier, date, stance and link; (3) a temporal "old news presented as new" check with both dates shown; (4) an explanation naming the rule that fired, plus LIME style highlights explicitly labelled as *not* deciding the verdict; (5) an offline mode so the demo cannot fail on college Wi-Fi.

**Screens** (master doc §16.1): *Home/Analyse* — tabs Headline · Article · URL, Online/Offline toggle, "Try example", "Analyse"; *Result* — verdict banner, confidence bar (Low < 0.5 / Medium 0.5–0.75 / High > 0.75), highlighted claims with stance chips, supporting vs. contradicting evidence columns, dates panel, style-signal highlights, uncertainty statement, "Download JSON"; *About* — class definitions, limitations, source list, team.

**Explanation panel**: one-sentence reason from the Jinja2 template of the fired rule (`src/explain/templates/`), per-claim stance summary, LIME top-10 tokens (`lime.lime_text.LimeTextExplainer`, 500 samples, cached per input hash) under the caption "Writing-style signals only — these do not decide the verdict".

**Uncertainty communication**: always present; e.g., "Only 1 reliable source found; this result could change as more coverage appears." UNVERIFIABLE always says "This does not mean the claim is false."

**Accessibility basics**: semantic HTML with labelled inputs; keyboard-operable tabs and buttons; verdict conveyed by text + icon, never colour alone; contrast ≥ 4.5:1; responsive on a phone screen; all evidence links open with source name and date in the link text.

# 5. Working Project — Deployment (5 marks)

## 5.1 What we built / delivered

One Docker image (`python:3.11-slim`, CPU-only torch wheel, ≈ 2.5 GB) used for local `docker compose` and the Hugging Face Space (Docker SDK, free CPU basic: 2 vCPU, 16 GB RAM). Render free tier (512 MB) runs the same Dockerfile in `MODE=lite` (TF-IDF + SVM, MiniLM, offline index, no DeBERTa) as a portability backup. `MODE=offline` skips all network calls and uses the FAISS index plus the pre-warmed `data/cache/evidence.sqlite`.

| Item | Value |
|---|---|
| Local run | `make setup` → `make run` (`uvicorn src.api.main:app --port 8000`) → `http://localhost:8000` |
| Docker | `docker compose -f docker/compose.yml up --build` (`make docker-build`, `make docker-run`) |
| Health / config | `GET /health` → `{"status":"ok","mode":"online","models":{"clf":"distilbert-welfake-v1","nli":"nli-deberta-v3-small"}}`; `GET /config` → mode, sources, thresholds |
| Env vars | `MODE` (online · offline · lite · classifier_only), `GOOGLE_FACTCHECK_API_KEY`, `MAX_EVIDENCE_PER_CLAIM`, `SEARCH_TIMEOUT_S`, `MODEL_DIR`, `CACHE_PATH`, `OLLAMA_URL` (optional); documented in `.env.example`; keys only via env / HF secrets, never in code |
| Model footprint | DistilBERT ≈ 260 MB fp32 (≈ 130 MB int8 optional), MiniLM ≈ 90 MB, nli-deberta-v3-small ≈ 570 MB, spaCy sm ≈ 13 MB, FAISS < 30 MB → **≈ 1 GB on disk; CPU inference ≤ 4 GB RAM** (NFR-6) |

# 10. Viva (35 marks) — Consolidated Question Bank

Fuller version: `docs/viva_qa.md` (60 Q&A). Every member must be able to answer every question here.

**Problem & datasets**

| Question | Answer |
|---|---|
| Define the five classes. | REAL = supported, no context issue; FAKE = refuted or fabricated; PARTIALLY TRUE = important claims split, or true core with wrong details; MISLEADING = true facts in wrong context (old news, wrong place, headline ≠ body); UNVERIFIABLE = no reliable evidence either way. |
| Why five classes, not two? | Real misinformation is mostly partial or out-of-context; binary output cannot express it and forces a guess when evidence is missing. |
| Why WELFake as primary? | Largest (72,134), merges four sources, near-balanced, fewer single-source artefacts than ISOT. |
| What is LIAR used for? | Fine-grained 6→5 mapping (true/mostly-true → REAL; half-true → PARTIALLY TRUE; barely-true → MISLEADING; false/pants-fire → FAKE), the 3-way head, and the offline index. |
| Why FEVER? | Only large dataset with claim–evidence stance labels; SUPPORTS/REFUTES/NEI → entailment/contradiction/neutral. |
| What is the Live Claims Set? | ~100 recent claims (Aug–Nov 2026) labelled from PolitiFact/Snopes/AltNews/BOOM, double-labelled, for end-to-end evaluation. |

**Preprocessing / EDA**

| Question | Answer |
|---|---|
| Which artefacts did you remove and why? | "WASHINGTON (Reuters) -" datelines, "(Reuters)", "Featured image via", "Read more:", URLs, handles — they predict the label without content. |
| How did you prevent train/test leakage? | SHA-1 exact + MinHash near-duplicate removal; check no duplicate spans splits; stratified 80/10/10 with seed 42 saved as ID lists. |
| What did EDA show that changed the design? | Length histograms → max_len 256; leakage tokens → artefact removal; ISOT dates 2015–2018 → temporal check; LIAR imbalance → class weights. |
| Why lower-case only for TF-IDF? | Transformers use cased/uncased tokenizers as trained; casing helps NER and claim heuristics. |

**Models & training**

| Question | Answer |
|---|---|
| Why DistilBERT over BERT-base? | 66 M params, ~97 % of BERT's performance, fits 4 GB GPU at fp16/batch 16/max_len 256, CPU inference < 1 s. |
| Why keep classical baselines? | Reference points, interpretable coefficients, CPU fallback (`MODE=lite`), viva-friendly. |
| Training recipe? | AdamW, lr 2e-5–5e-5, 2–3 epochs, warmup 0.06–0.1, weight decay 0.01, fp16, head-truncation of title + text. |
| How did CPU-only members train? | 10k subset, max_len 128, or Colab free T4; checkpoints shared via the HF Hub. |
| What is the stance model? | `cross-encoder/nli-deberta-v3-small`: premise = evidence, hypothesis = claim → entailment/contradiction/neutral with probability. |

**Tuning**

| Question | Answer |
|---|---|
| Classical search space? | GridSearchCV 5-fold: ngram (1,1)/(1,2), max_features 50k/100k/200k, sublinear_tf, C ∈ {0.1,1,10}, NB alpha ∈ {0.1,0.5,1}. |
| DistilBERT sweep? | lr {2e-5, 3e-5, 5e-5} × max_len {256, 512} on a 20k stratified subset (6 configs, epochs fixed at 3 with the best epoch kept), best config retrained on full train; selection by val macro-F1. |
| How were fusion thresholds tuned? | Grid over τ, min evidence count, N months on a 30-item dev slice of the Live Claims Set; the test slice was never touched. |
| Val–test gap? | `[fill]` — small, indicating no overfitting to val. |

**Retrieval & stance**

| Question | Answer |
|---|---|
| How are queries built? | Entities + numbers + head lemmas → `q_full`, `q_keywords`, `q_keywords + "fact check"`. |
| Sources and timeouts? | ddgs (8 results), Wikipedia REST top-2 intros, Google Fact Check `claims:search`, offline FAISS; 6 s each, concurrent; SQLite cache. |
| What is an evidence passage? | Top-3 sentences of a fetched page by MiniLM cosine to the claim, with domain, URL, date, tier. |
| Why source tiers? | Reliability weighting: fact-checkers 1.0, wires/official 0.8, Wikipedia 0.6, unknown 0.3, satire 0.0 + flag. |
| Why does a fact-checker rating override NLI? | A human verdict is stronger than a model guess; mapped to stance with p = 0.95. |

**Temporal & fusion**

| Question | Answer |
|---|---|
| Old-news rule? | Recency cue present AND (post date − median supporting-evidence date) ≥ 6 months. |
| Out-of-context rule? | GPE/EVENT/DATE entity conflict with ≥ 2 supporting passages; headline–body mismatch if NLI(body, headline) = REFUTES with p ≥ 0.7. |
| Walk through R0–R9. | R0 satire source → FAKE; R1 no evidence → UNVERIFIABLE; R2 Tier-1 "False" match → FAKE; R3 refuted, E ≥ 2 → FAKE; R4 supported + temporal flag → MISLEADING; R5/R6 split claims → PARTIALLY TRUE; R7 supported, E ≥ 2 → REAL; R8 single source tie-break; R9 else UNVERIFIABLE. |
| Why rules and not a learned fusion? | ~100 labelled items cannot train a fuser; rules are auditable and each verdict names its rule; learned fusion is a stretch goal to compare. |
| Why is the classifier limited to ±0.10? | Style is not fact; the invariant prevents a style model from contradicting evidence. |

**XAI**

| Question | Answer |
|---|---|
| What are the six explanation elements? | Verdict banner + reason, key claims with stance chips, evidence cards, dates panel, LIME style signals, uncertainty statement. |
| How does LIME work? | Perturbs the input by removing tokens, fits a local linear model on the classifier's outputs, reports top-10 token weights. |
| Is LIME faithful? | Locally approximate; good enough for style signals that do not decide the verdict; SHAP optional for figures. |

**Evaluation & limitations**

| Question | Answer |
|---|---|
| Why macro-F1? | Equal weight per class; UNVERIFIABLE and MISLEADING matter as much as FAKE. |
| Biggest limitation? | Dependence on retrieval: recent/hyper-local claims → UNVERIFIABLE; English only; small e2e test set. |
| How do you measure claim identification? | 50 articles, 2 annotators, Precision@3 (target ≥ 80 %), Cohen's κ. |
| How reproducible is this? | Pinned requirements, seed 42, `make data / train / eval`, cached evidence. |

**Deployment**

| Question | Answer |
|---|---|
| Modes? | online, offline, lite (Render 512 MB), classifier_only (ablation; UI marks it "style-based estimate, not fact-checked"). |
| Why not return 500 when DuckDuckGo blocks you? | NFR-8: each source fails independently; the pipeline continues with the rest and the offline index. |

**Research paper & ethics**

| Question | Answer |
|---|---|
| Could this tool be misused? | A wrong FAKE label can defame; hence evidence links, uncertainty text, "not a truth oracle" framing, and no autonomous action. |
| Privacy? | Only claim-derived search queries leave the machine; logs are local hashes. |
| Contributions in the paper? | (1) evidence-grounded 5-class verdicts with UNVERIFIABLE, (2) temporal old-news check, (3) honest leakage/cross-dataset study on a laptop budget. |

**Questions we should ask ourselves (the hard ones)**

| Question | Honest answer |
|---|---|
| Is there data leakage anywhere? | Guarded: dedup across splits, artefact removal, fusion thresholds tuned on a dev slice only, cache keyed by query not by label. Residual risk: WELFake merges sources that may overlap ISOT — we report it. |
| Why not just use an LLM? | Hallucinated evidence violates NFR-3; not reproducible; not free; not runnable on a laptop. An LLM may only paraphrase a template (stretch). |
| Where could the system still hallucinate? | Nowhere generatively; but NLI can *mis-read* evidence and the template can state a wrong count if retrieval is noisy — both are visible in the cards. |
| Is the source allowlist biased? | Yes: English, Indian/Western mainstream outlets; a reliable regional outlet gets 0.3. Mitigation: editable `sources.yaml`, weight ≠ veto, discussed as a limitation. |
| What happens on Hindi/Hinglish content? | Out of scope: UNVERIFIABLE with a message. Translation via IndicTrans2/NLLB is a stretch goal. |
| How is this different from Google Fact Check Explorer? | It only searches existing fact-checks; we produce a verdict when none exists, add temporal context, explanation, and offline use — and use it as one input. |
| Can the examiner break it? | Yes with a brand-new local claim → UNVERIFIABLE (by design), or a long opinion piece → few claims. We show that as intended behaviour. |
| Is ~100 items enough? | Enough to show ordering and failure modes, not to claim ±1 % precision; we say so. |
