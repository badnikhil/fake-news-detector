# End-to-end evaluation — Live Claims Set (eval split) — v2 (2026-11-12 improvement round)

Generated by `make eval-e2e` (`python -m src.eval.eval_e2e`). Items: the **65 `eval` items** of `data/live_claims/live_claims.csv` (the 30 `dev` items were used only for fusion tuning and are excluded). Each claim goes through `src.api.pipeline.analyze` (the code behind `POST /analyze`) as a headline with `published = claim_date` (else `factcheck_date`). Gold = the fact-checker's rating mapped to 5 classes (`data/live_claims/README.md`). Fusion thresholds: tau 0.8, min_evidence 3, N_months 6 (`fusion.yaml`). Content classifier used: distilbert-welfake-v1. Online = offline FAISS index + ddgs (DuckDuckGo) + Wikipedia; Google Fact Check was **not** used (no API key). Predictions: `train_logs/e2e_eval_{offline,online}_full_v2.jsonl`; confusion matrices `docs/figures/cm_e2e_v2.png`, `cm_e2e_offline_v2.png`.

## v2 (2026-11-12 improvement round) vs v1

v2 = v1 + (1) **leakage guard**: evidence whose normalised URL or canonical URL equals the item's own fact-check URL is removed before ranking (`analyze(exclude_urls=...)`, evaluation only); (2) **ClaimReview**: Tier-1 result pages are parsed for schema.org ClaimReview and, when the claim restates `claimReviewed` (the existing NLI / cosine ≥ 0.75 gate), the rating becomes the item's stance (p 0.95) with the LIAR / Live Claims mapping; (3) **dated claims** in the temporal check (`explicit_date_check`, `evidence_text_dates` in `fusion.yaml`). Thresholds tuned on the 30 dev items + temporal-set controls only (`fusion_thresholds.md`). The eval items were run once per mode.

|---|---|---|---|
| v1 online (no leakage guard) | 0.2308 | 0.1854 | 0.0789 |
| v1 online, own fact-check evidence removed post hoc (re-fused, v1 rules) | 0.1538 | 0.1260 | 0.0909 |

| v1 offline | 0.1077 | 0.0620 | 0.0968 |
| **v2 offline** | 0.0923 | 0.0343 | 0.0938 |

### Leakage disclosure

- **v1 was leaky:** in 34 of 65 v1 online runs the kept evidence contained the item's *own* fact-check page (the page the gold label comes from; matched on normalised URL — v1 stored no canonical URLs, so this is a lower bound). Removing those items post hoc and re-fusing gives the second row above.
- **v2 guard:** the item's own page was retrieved and removed for 35 of 65 items (35 evidence items).
- 22 of 65 items kept ≥ 1 *other* Tier-1 / rated fact-check matching the claim (cosine ≥ 0.75) — legitimate evidence (another fact-checker, or another article of the same publisher); 21 items had their own page as the only matching fact-check (removed).
- The guard is evaluation-only: in the deployed app, retrieving an existing fact-check is the intended behaviour.
